# astro-search

Локальний сервіс для фото нічного неба. Він знаходить зорі на кадрі, визначає, куди дивилася камера (plate solving), підписує зорі, планети й Місяць, рахує висоту над горизонтом і показує, наскільки точний результат.

Ідеї, архітектура й результати перевірок описані в [IDEAS.md](IDEAS.md).

**Стан:** готові бекенд (HTTP API) і вебсторінка.

## Запуск у Docker

```bash
docker build -t astro-search .
docker run --rm -p 127.0.0.1:8080:8080 -v astro-search-data:/data astro-search
```

Місце за замовчуванням (для фото без GPS, поки ви не вказали своє) — Львів. Інше задається змінними, напр. для Києва: `-e ASTRO_DEFAULT_LAT=50.4501 -e ASTRO_DEFAULT_LON=30.5234 -e ASTRO_DEFAULT_ELEVATION_M=180`.

- Сайт відкривається на `http://localhost:8080`, API — на `http://localhost:8080/api/`. Прив'язка до `127.0.0.1` означає, що з мережі до сервісу ніхто не достукається.
- Фронтенд збирається автоматично під час кожного запуску контейнера (`scripts/entrypoint.sh`, кілька секунд). Залежності Node вже лежать в образі, тож збірка працює офлайн. Якщо вона не вдасться, віддається версія, зібрана ще під час `docker build`.
- Інтернет потрібен лише під час збірки: вона завантажує пакети й каталог зір HYG і генерує базу tetra3rs. Готовий контейнер працює офлайн.
- Задачі зберігаються в томі `astro-search-data`, тож переживають перезапуск контейнера.

### Правка сторінки без перезбирання образу

Змонтуйте вихідний код фронтенду й перезапускайте контейнер: entrypoint збере сторінку заново.

```bash
docker run --rm -p 127.0.0.1:8080:8080 -v astro-search-data:/data \
  -v ./frontend/src:/app/frontend/src:ro -v ./frontend/index.html:/app/frontend/index.html:ro astro-search
```

`-e ASTRO_WEB_BUILD=0` вимикає збірку на запуску.

### За зворотним проксі

Якщо перед контейнером стоїть nginx чи інший проксі, дозвольте в ньому великі запити, інакше RAW-файли відхилятимуться з кодом 413 (у nginx за замовчуванням лише 1 МБ):

```nginx
client_max_body_size 300m;   # як ASTRO_MAX_UPLOAD_MB
proxy_request_buffering off; # передавати файл одразу, без буфера на диску проксі
```

## Запуск без Docker (для розробки)

Потрібні Linux і Python 3.10+. astrometry.net необов'язковий: без нього працює лише tetra3rs.

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python scripts/prepare_data.py --out ./catalog
sudo apt install astrometry.net astrometry-data-tycho2-10-19   # необов'язково

(cd frontend && npm ci && npm run build)                       # сторінка в frontend/dist
ASTRO_CATALOG_DIR=./catalog python -m astro_search             # сервер на 127.0.0.1:8080
ASTRO_CATALOG_DIR=./catalog python -m astro_search.cli photo.dng --out result.json   # без сервера
```

Перевірка точності після змін у пошуку зір чи уточненні: `ASTRO_CATALOG_DIR=./catalog python scripts/check_accuracy.py` (синтетичні кадри з відомою «правдою»: без дисторсії, бочка, «хвиляста» дисторсія телефона, вузьке поле; зорі по всьому кадру, лише в половині чи чверті, лише яскраві; похибка рахується по всьому кадру, зокрема там, де зір немає; код 1, якщо щось поза порогами).

Для роботи над сторінкою з гарячим перезавантаженням: запустіть сервер, а поруч `cd frontend && npm run dev` (Vite на `http://localhost:5173/static/`, запити `/api` йдуть на `127.0.0.1:8080`; інша адреса — через `ASTRO_API`).

## Налаштування (змінні середовища)

| Змінна | За замовчуванням | Що задає |
|---|---|---|
| `ASTRO_DATA_DIR` | `./data` (у Docker `/data`) | де зберігаються задачі |
| `ASTRO_CATALOG_DIR` | `./catalog` (у Docker `/opt/astro-catalog`) | підготовлені каталог і база tetra3rs |
| `ASTRO_HOST`, `ASTRO_PORT` | `127.0.0.1`, `8080` | адреса сервера |
| `ASTRO_MAX_UPLOAD_MB` | `300` | найбільший розмір файлу |
| `ASTRO_DEFAULT_LAT`, `ASTRO_DEFAULT_LON`, `ASTRO_DEFAULT_ELEVATION_M` | Львів: `49.8397`, `24.0297`, `300` | місце, якщо його не вказано, у EXIF немає GPS і браузер не передав звичне місце; результат тоді попереджає, що місце невідоме |
| `ASTRO_ASTROMETRY_CPULIMIT` | `60` | скільки секунд дозволено astrometry.net |
| `ASTRO_WEB_DIR` | `./frontend/dist` (у Docker `/app/web`) | зібрана сторінка |
| `ASTRO_WEB_BUILD` | `1` | у Docker: `0` вимикає збірку фронтенду на запуску |

## API

| Запит | Що робить |
|---|---|
| `GET /api/health` | стан: доступні розв'язувачі, розмір каталогу, довжина черги |
| `POST /api/jobs` | завантажити фото (multipart), відповідь `202` з `id` задачі |
| `GET /api/jobs` | список задач, нові першими |
| `GET /api/jobs/{id}` | статус (`queued` → `running` → `done` / `failed`) і, коли готово, `result` |
| `GET /api/jobs/{id}/preview` | JPEG-прев'ю в тих самих піксельних координатах, що й результат |
| `GET /api/jobs/{id}/original` | завантажений оригінал |
| `DELETE /api/jobs/{id}` | видалити задачу (крім тієї, що саме обробляється) |
| `POST /api/jobs/{id}/observation` | новий час і/або місце для готового кадру (JSON `{"time", "lat", "lon", "elevation_m"}`): висоти, планети, Місяць і горизонт перераховуються за ~0,2 с без повторного розпізнавання |

Поля форми `POST /api/jobs`:

| Поле | Обов'язкове | Опис |
|---|---|---|
| `file` | так | JPG, PNG, TIFF, WebP, HEIC або RAW (DNG, CR2, NEF, ARW…) |
| `time` | ні | час зйомки ISO 8601 з поясом, напр. `2024-11-01T22:30:01+02:00`; має пріоритет над EXIF |
| `lat`, `lon` | ні | координати місця зйомки, передаються разом |
| `elevation_m` | ні | висота над рівнем моря |
| `fov_deg` | ні | підказка: горизонтальне поле зору в градусах |
| `fallback_lat`, `fallback_lon`, `fallback_elevation_m` | ні | «звичне місце»: береться, лише якщо в EXIF немає GPS (сторінка надсилає його сама, якщо ви його запам'ятали) |

Місце спостереження обирається так: `lat`/`lon` з форми → GPS з EXIF → звичне місце → місце за замовчуванням сервера.

```bash
curl -X POST -H 'Content-Type: application/json' \
  -d '{"lat": 50.4501, "lon": 30.5234, "time": "2025-04-19T21:54:31+03:00"}' \
  http://localhost:8080/api/jobs/<id>/observation
```

```bash
curl -F file=@20241101_222953.dng http://localhost:8080/api/jobs
curl http://localhost:8080/api/jobs/<id>
```

### Що містить `result`

Усі піксельні координати рахуються від лівого верхнього кута (0, 0): `x` — вправо, `y` — вниз. Вони збігаються з пікселями прев'ю.

| Поле | Зміст |
|---|---|
| `image` | розмір кадру і тип (`raster`, `raw`, `raw-linear`) |
| `observation` | час (UTC) і його джерело, місце і його джерело (`user` / `exif` / `fallback` — звичне місце / `default` — справжнє невідоме), попередження про час і місце, дані камери з EXIF |
| `solved`, `solution` | центр кадру, поле зору, масштаб ″/px, напрямок «вгору», розв'язувач, скільки зір збіглося, похибка (rms, медіана, p90, макс.), `distortion` — обрана модель дисторсії і похибка кожної моделі на зорях, яких підгонка не бачила, WCS-заголовок FITS |
| `stars` | зорі каталогу до 6,5m на кадрі: назва, позначення, величина, `x`/`y`, відхилення від знайденої на кадрі точки (`in_fit: false` — точка є, але в підгонку не ввійшла: пересвічена чи тісна подвійна); з відомим часом — висота й азимут |
| `constellations` | лінії сузір'їв МАС у кадрі: `id` (абревіатура, напр. `UMa`), `lines` — ламані в пікселях, `label` — точка для назви |
| `bodies` | планети, Місяць, Сонце на кадрі: `x`/`y`, величина, висота й азимут, відхилення від найближчої знайденої точки |
| `horizontal` | висота й азимут центру кадру, діапазон висот, куди на кадрі вказує зеніт, сітка висоти/азимута як ламані |
| `detections` | усі знайдені на кадрі точки: `[x, y, потік]` |
| `warnings`, `timings` | попередження і час кожного етапу |

Планети, висота над горизонтом і сітка рахуються лише тоді, коли відомий час зйомки.

## Вебсторінка

Vite + TypeScript без фреймворків (`frontend/`), усе працює офлайн.

- Завантаження перетягуванням у будь-яке місце вікна, з прогресом. Час (з часовим поясом), координати («Моє місце зараз»), висота й поле зору — необов'язкові.
- Поки кадр обробляється, на його прев'ю крутиться «радар».
- Кадр із SVG-накладкою: зорі каталогу (суцільне коло — знайдена на кадрі, пунктир — ні), планети й Місяць, лінії й назви сузір'їв, усі знайдені точки, сітка висоти й азимута з горизонтом і сторонами світу. Шари вмикаються кнопками або клавішами, межа зоряної величини — повзунком. Підписи не накладаються один на одного.
- Розкладка: ліва панель (завантаження й кадри) згортається у вузьку смужку з «+» і мініатюрами (кнопка в шапці або `[`), права панель результату ховається (`]`), є повний екран (`F`). Вид при цьому тримає центр кадру, стан панелей пам'ятається. На вужчих за 1500 px екранах ліва панель спершу згорнута; на телефоні вона висувна. Коли форму не видно, перетягнутий чи вибраний через «+» файл завантажується одразу — час і місце можна вказати вже на сторінці результату.
- Підписи за наближенням: власні назви й грецькі позначення видно завжди, номери Флемстіда — з наближення ×1,8, HIP/HR — з ×3,5. Межа зоряної величини за замовчуванням підбирається так, щоб на кадрі було не більше ~250 кружечків.
- Масштабування коліщатком, щипком і подвійним кліком, перетягування. Під курсором видно α/δ (TAN-SIP з WCS-заголовка) і приблизні висоту й азимут; унизу — шкала в кутових одиницях.
- Клік по об'єкту відкриває картку: величина, координати, висота й азимут, відхилення від знайденої точки.
- Панель «Огляд»: куди дивилася камера, мінікарта неба з контуром кадру, сузір'я в кадрі (клік підсвічує лінії й наближає), найяскравіші зорі, дані зйомки. «Об'єкти»: пошук і список. «Точність»: rms/медіана/p90/макс., гістограма відхилень, планети проти розрахунку, час етапів. «Дані»: попередження й завантаження (кадр із підписами в PNG, JSON, WCS-заголовок, оригінал).
- Місце зйомки: самі зорі його не видають (α/δ від місця не залежать), тож воно береться з форми, GPS в EXIF або вашого звичного місця. Якщо місце невідоме, результат прямо про це каже й пропонує його вказати; змінити час і місце можна й потім — небо перерахується без повторного розпізнавання. Звичне місце (позначка «запам'ятати») зберігається в браузері й підставляється для наступних фото без GPS. У поле широти можна вставити пару «широта, довгота», як її копіюють з карт.
- Нічний режим (N): усе червоне, щоб не збивати темнову адаптацію очей.

## Як це працює

1. **Читання** (`ingest.py`): JPG/PNG/HEIC через Pillow; RAW через LibRaw (`rawpy`); лінійні DNG (зокрема Samsung Expert RAW з JPEG XL) через `tifffile` + `imagecodecs`. Час, витримка, фокусна відстань і GPS беруться з EXIF.
2. **Пошук зір** (`stars.py`): віднімання фону, локальні максимуми вище 5σ. Відкидаються лінії (рами вікна), розмиті плями, гарячі пікселі, а на JPG ще й насичено кольорові точки (намальовані підписи, вогні літаків).
3. **Plate solving** (`solve.py`): спершу tetra3rs (мілісекунди), а якщо не вийде — astrometry.net. Будь-який із них дає лише початкове наближення.
4. **Уточнення** (`solve.py`, `distortion.py`): зорі каталогу HYG зіставляються зі знайденими точками, викиди відкидаються, підганяється TAN з дисторсією об'єктива. Моделі дисторсії — від чистої TAN до полінома 3-го степеня з радіальними членами r⁴, r⁶ (типова «хвиляста» дисторсія ширококутних об'єктивів телефонів) і полінома 5-го степеня. Підгонка лінійна в нормованих координатах, а модель обирає перехресна перевірка: береться найпростіша, не помітно гірша за найкращу на зорях, яких підгонка не бачила. Результат записується стандартним TAN-SIP. Тому точність і звіт однакові незалежно від розв'язувача.
5. **Небо** (`sky.py`): планети й Місяць з ефемериди JPL de421 на точний час і з точки спостереження, висота й азимут, рефракція.
